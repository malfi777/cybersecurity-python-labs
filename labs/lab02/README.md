Лабораторна робота №2: Розробка консольних утиліт для задач кібербезпеки

Варіант 4: Парсер логів аутентифікації SSH / Linux Auth Log

Цей проєкт складається з двох основних частин:

Демонстрація принципів об'єктно-орієнтованого програмування (ООП) на прикладі системи керування користувачами.

Практична консольна утиліта (CLI) для аналізу системних журналів auth.log та виявлення атак типу Bruteforce.

Структура проєкту

main.py — головний диспетчер (точка входу). Обробляє аргументи командного рядка та запускає відповідне завдання (demo або analyze).

task1.py — реалізація Завдання 1. Містить ООП-моделі системи безпеки: User, Admin, Session, AuditLog та UserAccount.

task2.py — реалізація Завдання 2 (Варіант 4). Консольна утиліта для пошуку підбору паролів (брутфорс) у логах SSH із застосуванням алгоритму "ковзного вікна".

data/data_v04/ — директорія з тестовими даними (наприклад, auth.log).

Встановлення та налаштування

Переконайтеся, що у вас встановлено Python 3.10+ та активовано віртуальне середовище.

Встановіть необхідні залежності проєкту (наприклад, лінтер ruff) з кореневої директорії:

pip install -r requirements.txt


Запуск програми

Програма підтримує дві основні команди, які передаються через головний файл main.py. Запуск здійснюється з кореневої папки репозиторію.

Завдання 1: Демонстрація ООП

Запускає тестовий сценарій, який демонструє створення користувачів, роботу з правами адміністратора, валідацію пошти, роботу сесій (таймаути) та запис подій у журнал аудиту.

python -m labs.lab02.main demo


Завдання 2: Аналізатор логів (Bruteforce Detector)

Запускає утиліту для аналізу файлу auth.log.

Параметри CLI:

--auth-log (обов'язковий) — шлях до файлу журналу auth.log.

--threshold (необов'язковий) — ліміт невдалих спроб перед блокуванням (за замовчуванням: 5).

--window-min (необов'язковий) — часове вікно в хвилинах для підрахунку спроб (за замовчуванням: 5).

--output-json (необов'язковий) — шлях для збереження JSON-звіту із заблокованими IP-адресами.

Приклад запуску:

python -m labs.lab02.main analyze --auth-log labs/lab02/data/data_v04/auth.log --threshold 5 --window-min 5 --output-json labs/lab02/data/report.json


Очікувана поведінка при помилках:

Якщо вказаного файлу журналу не існує, програма виведе відповідне повідомлення про помилку в консоль і завершить роботу.

Програма ігнорує системне сміття у лог-файлі та обробляє лише рядки, що стосуються успішної або невдалої аутентифікації SSH.
